# 01 · עץ השלוחות

> סטטוס: **סבב שני סגור**. החלטות: D-102–D-105. הגישה של D-101 (מודל היסטוריה) הוחלפה ב-D-105.
> סימון ⚠️ = הנחה שצריך לאמת מול ה-API האמיתי.

## 1. הגישה (D-105)

- **במערכת יש עץ אחד: העץ הנוכחי של ידע פון.** הוא מתעדכן בכל סנכרון. אין גרסאות ואין היסטוריית מצב.
- **יומן ההאזנות שומר תמיד את הנתיב (`class_path`) והשם (`class_name`) הגולמיים**, כפי שהגיעו. השיוך לשלוחה הוא שדה מחושב, ואפשר לחשב אותו מחדש בכל רגע.
- **התכנון של העץ העתידי הוא מודול צדדי** (מסמך 06): טיוטות, הערות, דוח פערים ומיפוי מהעץ הקיים לעתידי. הוא לא נוגע בנתונים החיים.
- **במעבר לעץ החדש:**
  1. מוחקים את העץ ואת טבלאות הסיכום.
  2. מייבאים את העץ החדש מידע פון.
  3. משייכים מחדש את ההאזנות הישנות לשלוחות החדשות לפי המיפוי ממודול התכנון.
  4. יומן ההאזנות הגולמי והמיפוי לא נמחקים לעולם. כך נשמרים D-005 ו-D-012 בלי מודל היסטוריה.

## 2. מה מגיע מה-API

ממקור `/api/system/sclass/` (רשימה לפי `parent`, עד 100 בעמוד) ו-`/api/system/sclass/{id}/` (פרטים):

| שדה | משמעות | הערה |
|---|---|---|
| `id` | מזהה השלוחה בידע פון | מפתח הזהות (D-017) |
| `path` | נתיב מלא, למשל `1.2.1.4.1` | מקטע יכול להיות מספר, `*` או `#`. עד 150 תווים |
| `order` | מיקום תחת האב | זהה למקטע האחרון (אומת ברמה העליונה) |
| `name` | שם, עד 100 תווים | |
| `cls_type` | סוג שלוחה | מקושר ל-`/api/sclass-types/` |
| `settings` | הגדרות לפי סוג (JSON) | נשמר כפי שהוא |
| `open_msg_id`, `sf_name_id`, `sclass_audio_name_id` | הפניות להקלטות | הודעת פתיחה, הודעה זמנית ושם השלוחה |
| `count_sub_sclass` | מספר תתי-שלוחות | לבדיקת שלמות הסריקה |
| `conf_id` | `<מוסד>.<נתיב>`, למשל `7291.1.1.4` | כמו תיקיית ההקלטות בשמות MSG. ⚠️ האם מתעדכן בהזזה |
| `var_bool` | לא מתועד | נשמר גולמי ⚠️ |
| `teacher_phone`, `pin_code_extension`, `pin_code_admin_only` | רגישים | ראו §5 |

- ה-API לא מחזיר את מזהה האב. הוא נגזר מהבקשה (`parent=`).
- `teacher_phone` מגיע בפועל כמחרוזת מופרדת בפסיקים, כ-`""` או כ-`null`. הוא מנורמל לרשימת מספרים.
- `name` יכול להיות `null` או מספר כטקסט.
- `settings` מגיע מלא גם ברשימה. ⚠️ צריך להשוות לפרטי שלוחה בודדת.

**ברמה העליונה של הקו יש 8 שורשים.** `1` הוא התפריט הראשי, ו-`2` הוא תפריט נפרד שבו נמצאים `2.6.x`. השאר הם שלוחות מעבר והודעות (`3`, `4`, `6`), שלוחות API (`5`, `111`) ו-SENDZ (`1000`). פירוט ב-`docs/sources/api-samples.md`.

**מיום המדגם (27.3):**
- 185 נתיבים. שני שורשים: `1` ו-`2` (רק `2.6.1`–`2.6.3`).
- עומק עד 8 רמות, ומקטעים רב-ספרתיים (33, 100, 101, 102).
- לכל נתיב יש שם אחד ושלוחה אחת.
- רשומה אחת הגיעה בלי נתיב ובלי שם.

## 3. ישויות

**`extension`** · שלוחה בעץ הנוכחי. שורה אחת לכל `id`.
| שדה | תיאור |
|---|---|
| `sclass_id` | מפתח ראשי |
| `parent_sclass_id` | |
| `path`, `path_segments[]`, `depth`, `order` | `path_segments` משמש למיון נכון (`1.10` אחרי `1.9`) |
| `name`, `cls_type`, `settings` | |
| `open_msg_id`, `sf_name_id`, `sclass_audio_name_id` | הפניות להקלטות |
| `count_sub_sclass` | |
| `is_open`, `required_login`, `time_active` | מתוך `settings`, כשדות נפרדים לבדיקות תקינות ולתצוגה |
| `conf_id`, `var_bool` | |
| `sensitive` (מוצפן) | `teacher_phone`, `pin_code_extension`, `pin_code_admin_only` |
| `first_seen_at`, `last_synced_at` | |
| `missing_since` | שלוחה שלא חזרה בסנכרון האחרון. מסומנת, לא נמחקת, כדי שהאזנות שלה לא יתייתמו |

**`extension_path_alias`** · מנגנון קטן ל-D-017, לא מודל היסטוריה.
כשהסנכרון מגלה ששלוחה קיימת קיבלה נתיב חדש, הנתיב הקודם נשמר כאן. כך האזנות מהנתיב הישן ממשיכות להשתייך לאותה שלוחה. דוגמה: 836681 עברה מ-`1.7.2.2.11.3.2` ל-`1.7.2.2.11.100.2`, וארבעה צאצאים זזו איתה.
| שדה | תיאור |
|---|---|
| `old_path`, `sclass_id` | |
| `detected_at` | |

**`extension_type`** · מ-`/api/sclass-types/`: `cls_type`, שם, קבוצה, סכמה.

**הערות ל-`settings`:** נשמר כ-JSON כפי שהגיע, יחד עם הסכמה של הסוג מ-`extension_type`, לתצוגה עם כותרות בעברית.

**`tree_sync_run`** · כל ריצת סנכרון עץ
`run_id`, `started_at`, `finished_at`, `status`, `node_count`, `completeness_ok` (האם `count_sub_sclass` תאם למספר הילדים שנמצאו).
התגובות הגולמיות של הריצה האחרונה נשמרות לבדיקה, בלי היסטוריה.

### שיוך האזנה לשלוחה

לכל האזנה נשמרים `sclass_id` מחושב ו-`resolution`:
1. **`path`**: הנתיב קיים בעץ הנוכחי.
2. **`alias`**: הנתיב נמצא ב-`extension_path_alias`.
3. **`unresolved`**: לא נמצא. ההאזנה נכנסת לרשימת "לא משויך", עם הנתיב והשם הגולמיים. מנהל יכול לשייך ידנית.

**בדיקת שפיות:** אם השם בהאזנה שונה לגמרי מהשם הנוכחי של השלוחה, ההאזנה מסומנת לבדיקה. השיוך עצמו לא משתנה.

**`extension_setting_ref`** · הפניות משלוחה לשלוחה מתוך `settings`. נגזרת, ומחושבת מחדש בכל סנכרון.
בהגדרות של ידע פון, הקשרים בין שלוחות נשמרים כמחרוזת נתיב או שם, ולא כמזהה: `record_to`, `more_public_to`, `play_from_other_sclass`, `success_move_to_sclass`, `goto_sclass`, `on_exit_goto` ועוד (פירוט ב-`docs/sources/api-samples.md`).
רשימת המפתחות שמפנים לשלוחות מנוהלת לפי סוג שלוחה, ומתעדכנת כשמגיעות סכמות נוספות.
| שדה | תיאור |
|---|---|
| `sclass_id`, `setting_key` | למשל `836681`, `more_public_to` |
| `raw_value` | הערך כפי שהוא, למשל `1.1.1,2.6.1` |
| `ref_kind` | `record_to` / `publish_to` / `play_from` / `play_from_all` (`*`) / `exclude` (`~`) / `zintuk_source` / `register_to` / `move_to` / `external_line` / `hangup` |
| `target_text` | נתיב או שם בודד אחרי פיצול לפי פסיקים |
| `target_sclass_id` | מזהה השלוחה שהטקסט מצביע עליה כרגע |
| `status` | `ok` / `broken` (הנתיב לא קיים) / `by_name` / `external` (קו אחר) |

**למה זה חשוב:**
1. **שלוחות מקושרות (D-015) מתקבלות אוטומטית** מהנתונים: `extension_link` עם `source_kind = settings`, לצד קישורים ידניים.
2. **הסבר לזרימת התוכן.** הקלטה שהוקלטה ב-`1.1.4.2` ונשמעת ב-`1.1.4.1`, כנראה בגלל `record_to` או `more_public_to`. זה מסייע לשיוך שיעורים (D-018) ולסיכום ברמת השיעור (D-014).
3. **בדיקת תקינות:** הפניה לנתיב שלא קיים מקבלת `broken`.
   - מועמדת לבדיקות התקינות (D-012, D-016).
   - **קריטית במעבר לעץ החדש:** כל הפניה כזו צריכה להיכתב מחדש לנתיב החדש. מודול התכנון יפיק את רשימת ההפניות שצריך לעדכן.

## 4. העץ ההתחלתי

- הסריקה מ-21.10.2026 מיובאת כעץ ההתחלתי (D-103). היא גם הבסיס שלפיו מופה הארכיון.
- כשיהיה טוקן, הסנכרון הראשון מה-API מעדכן אותה. נתיבים שזזו בינתיים נכנסים ל-`extension_path_alias`.

## 5. שדות רגישים (D-102)

| שדה | מה עושים |
|---|---|
| `pin_code_extension`, `pin_code_admin_only` | נשמרים במלואם, מוצפנים. בתצוגה מופיע רק "יש קוד / אין קוד". הערך נחשף רק למנהל הראשי |
| `teacher_phone` | נשמר במלואו, מוצפן ומוסתר. נחשף רק למנהל הראשי. משמש לשיוך מרצה לשלוחה |

- כל חשיפה נרשמת ביומן גישה.
- הערכים לא עוברים לצ'אט ולא לטבלאות הסיכום.

## 6. מאפייני שלוחה שהמערכת מנהלת (D-015, D-104)

המאפיינים צמודים ל-`sclass_id`. במעבר לעץ החדש הם עוברים לשלוחות החדשות לפי המיפוי ממודול התכנון.

**`extension_profile`** · שורה לכל שלוחה
| שדה | תיאור |
|---|---|
| `sclass_id` | |
| `content_type` | מרשימה מנוהלת: שיעורים, הודעות, חזרה, צינתוק, הסבר ועוד |
| `short_description` | תיאור פנימי |
| `caller_explanation` | ההסבר שהמתקשר שומע |
| `renewal_rule` | יומי / שבועי ביום X / חודשי / לא קבוע / סדרה סגורה |
| `renewal_grace` | כמה זמן אחרי המועד הצפוי להתריע על פרק שלא עלה |
| `updated_by`, `updated_at` | |

**`extension_lecturer`** · `sclass_id`, `lecturer_id`, `role` (ראשי / שותף / אורח).

**`tag`, `extension_tag`** · `tag(tag_id, name, kind: tag/topic, parent_tag_id)` ו-`extension_tag(sclass_id, tag_id)`.

**`extension_link`** · שלוחות מקושרות: `from_sclass_id`, `to_sclass_id`, `link_kind`, `note`.
סוגי קישור:
- `mirror`: כניסה חלופית לאותו תוכן, כמו `2.6.x` מול `1.1.x`.
- `copy_target`: "יועתקו גם ל-310".
- `redirect`: "להרשמה מועבר ל-90".
- `related`.
- `source_kind`: `manual` או `settings`. קישורים מסוג `settings` נגזרים אוטומטית מ-`extension_setting_ref`, ומתעדכנים בכל סנכרון.

**`attribute_change`** · יומן שינויים
`entity`, `entity_id`, `field`, `old_value`, `new_value`, `changed_by`, `changed_at`.
`source_kind` יכול להיות:
- `manual`
- `inherited_via_mapping`
- `suggested_from_draft`
- `suggested_from_data`

**במעבר:**
- הזזה (אותו `id`): לא צריך להעביר כלום.
- בנייה מחדש (1→1): המאפיינים מועתקים אוטומטית.
- מיזוג ופיצול: מנהל מאשר מה עובר. במרצים ובתגיות ברירת המחדל היא איחוד.

## 7. נקודות פתוחות

- תדירות סנכרון העץ. הצעה: פעם ביום, לפני משיכת ההאזנות. ⚠️ לא ידועה מגבלת קצב ל-`system/sclass`. ייסגר בנושא הסנכרון.
- ⚠️ האם ה-API מחזיר שלוחות שנמחקו מחיקה רכה.
- דוגמה מהדפים הגולמיים של סריקת 21.10. תתבקש בנושא הייבוא.

## 8. הנחות לאימות מול ה-API

**אומת:** `order` שווה למקטע האחרון. `cls_type` מגיע באותיות גדולות. `teacher_phone` הוא מחרוזת.

1. `parent=<id>` מחזיר רק ילדים ישירים, ו-`count_sub_sclass` סופר רק אותם.
2. `id` של שלוחה לא ממוחזר.
3. `conf_id`: האם מתעדכן כששלוחה זזה. המשמעות של `var_bool`.
4. ערכי ההפניה ב-`settings` הם נתיבים מלאים (`1.1.4.1`), ולא יחסיים.
5. `settings` ברשימה זהה ל-`settings` בפרטי שלוחה בודדת.
