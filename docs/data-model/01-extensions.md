# 01 · עץ השלוחות: ישויות, זהות והיסטוריית נתיבים

> סטטוס: **נושא סגור (סבב ראשון)**. החלטות: D-101–D-104.
> סימון ⚠️ = הנחה שצריך לאמת מול ה-API האמיתי.

## 1. הבעיה שהמודל פותר

1. **ההאזנות לא מכילות מזהה שלוחה.** רשומת `sfu-list` מכילה רק `class_path` ו-`class_name` כפי שהיו ברגע ההאזנה.
   כדי לספור לפי מזהה (D-017), צריך לדעת **איזו שלוחה ישבה בנתיב הזה באותו זמן**.
2. **העץ זז.** שלוחה 836681 עברה מ-`1.7.2.2.11.3.2` ל-`1.7.2.2.11.100.2`, וכל תת-העץ שלה עבר איתה.
3. **אין ל-API היסטוריה של העץ.** `/api/system/sclass/` מחזיר רק את המצב הנוכחי. כל היסטוריה נבנית אצלנו, מצילומים שלנו.
4. **היסטוריה קודמת לצילום הראשון.** הארכיון (30.3–20.10) מופה לפי סריקת עץ אחת מ-21.10.
   ה-MANIFEST אומר במפורש: *"not proof of historical identity"*.

## 2. מה ידוע על המקור

### מ-`/api/system/sclass/` (רשימה, לפי `parent`, עד 100 בעמוד) ו-`/api/system/sclass/{id}/` (פרטים)

| שדה | משמעות | הערה למודל |
|---|---|---|
| `id` | מזהה השלוחה בידע פון | **מפתח הזהות** |
| `path` | נתיב מלא, למשל `1.2.1.4.1` | משתנה. מקטע יכול להיות מספר, `*` או `#`, עד 150 תווים |
| `order` | מיקום תחת האב | בדרך כלל זהה למקטע האחרון ⚠️ |
| `name` | שם, עד 100 תווים | משתנה |
| `cls_type` | סוג השלוחה (LMENU, MB, playfile...) | מקושר ל-`/api/sclass-types/` |
| `conf_id` | למשל `XXXXX.1` | משמעות לא ברורה ⚠️ |
| `settings` | הגדרות לפי סוג (JSON) | נשמר כ-JSON עם hash לזיהוי שינוי |
| `open_msg_id`, `sf_name_id`, `sclass_audio_name_id` | הפניות להקלטות (`streamfile`) | הודעת פתיחה, הודעה זמנית ושם השלוחה |
| `count_sub_sclass` | מספר תתי-שלוחות | לבדיקת שלמות הסריקה |
| `var_bool` | לא מתועד | נשמר גולמי ⚠️ |
| `teacher_phone` | טלפונים של מורים | **רגיש** (ראו §6) |
| `pin_code_extension`, `pin_code_admin_only` | קודים סודיים | **רגיש מאוד** (ראו §6) |

- ה-API **לא מחזיר את ה-id של האב**. האב נגזר מהבקשה (`parent=`) או מקיצור הנתיב.
- השדה `teacher_phone` מגיע פעם כמערך (`[]`) ופעם כמחרוזת (`""`). זו עוד דוגמה לחוסר האחידות.

### מיום המדגם (27.3)

- 185 נתיבים. שני שורשים: `1` (181 נתיבים) ו-`2` (רק `2.6.1`–`2.6.3`).
- עומק עד 8 רמות. יש מקטעים רב-ספרתיים: 33, 100, 101, 102.
- ביום אחד: נתיב ↔ שלוחה ביחס 1:1, ולכל נתיב יש שם אחד.
- רשומה אחת הגיעה בלי `class_path` ובלי `class_name`.
- **שמות הקלטות מסוג `MSG` מכילים את נתיב ההקלטה בזמן ההקלטה:**
  `7291/7291-1-1-4-2/records/MSG-<טלפון>-26-03-2026_08-56-34.wav` ← הוקלט ב-`1.1.4.2`.
  זו ראיה נוספת לנתיב שהיה קיים בתאריך מסוים, גם לפני שהיה לנו צילום.
- ב-MANIFEST נרשם שבאותה סריקה **הרשימה והפרטים החזירו נתיבים שונים** לאותה שלוחה.
  הסריקה לא אטומית: היא נמשכת שעות (יותר מ-6,400 בקשות), והעץ יכול להשתנות באמצעה.

## 3. שכבות

```
גולמי (append-only)          מנורמל                        נגזר
─────────────────────         ──────────────────────        ──────────────────────
tree_scan                ┐    extension                     path_assignment
raw_api_page             ├──► extension_observation  ──►    (נתיב+זמן → שלוחה)
                         │    extension_version             extension_current (תצוגה)
sfu (שמות נתיב בהאזנות) ─┘    path_name_evidence            tree_change_event
```

- **שכבת הגולמי לא משתנה לעולם.** כל בנייה מחדש של השכבות המנורמלות נעשית ממנה.
- **שכבת הנגזר** ניתנת לחישוב מחדש. שיוך מחדש = חישוב מחדש של `path_assignment` ושל מה שתלוי בו.

## 4. ישויות

### 4.1 שכבת הגולמי

**`tree_scan`** · סריקת עץ אחת
| שדה | תיאור |
|---|---|
| `scan_id` | מזהה |
| `source` | `api` / `archive_import` (למשל הסריקה מ-21.10 שמוזכרת ב-MANIFEST) |
| `started_at`, `finished_at` | גבולות הסריקה |
| `status` | `complete` / `partial` / `failed` |
| `request_count`, `node_count` | לבקרה |
| `completeness_check` | האם `count_sub_sclass` של כל אב תאם למספר הילדים שנמצאו |

**`raw_api_page`** · כל תגובת API כפי שהתקבלה (משותף לכל הנושאים)
| שדה | תיאור |
|---|---|
| `raw_id` | מזהה |
| `endpoint`, `params` | למשל `system/sclass`, `{parent: 268781, page: 2}` |
| `scan_id` / `sync_run_id` | לאיזו ריצה שייך |
| `received_at` | זמן קבלה (UTC) |
| `http_status`, `body` (דחוס), `body_sha256` | התוכן המלא |

### 4.2 שכבת המנורמל

**`extension`** · שלוחה. שורה אחת לכל `id` של ידע פון, שלא משתנה לעולם.
| שדה | תיאור |
|---|---|
| `sclass_id` | המזהה של ידע פון. מפתח ראשי |
| `first_seen_at`, `last_seen_at` | בכל המקורות |
| `gone_since` | נעלמה מהסריקות (ידע פון מוחקת מחיקה רכה. ⚠️ האם שלוחה מחוקה עדיין מוחזרת?) |
| `origin` | `observed_in_tree` / `known_from_listening_only` (שלוחה שראינו רק בארכיון ולא בעץ) |

**`extension_observation`** · מה ראינו על שלוחה, מתי ומאיזה מקור. שורה לכל תצפית.
| שדה | תיאור |
|---|---|
| `sclass_id`, `scan_id`, `raw_id` | מקור |
| `source_kind` | `list` / `detail` |
| `observed_at` | זמן קבלת התגובה (לא זמן תחילת הסריקה) |
| `path`, `parent_sclass_id`, `order`, `name`, `cls_type`, `conf_id` | השדות |
| `settings_hash`, `media_refs` | הגדרות והפניות להקלטות |

**`extension_version`** · היסטוריית המצב של שלוחה (SCD2). גרסה חדשה נפתחת בכל שינוי באחד השדות.
| שדה | תיאור |
|---|---|
| `sclass_id`, `version_no` | |
| `path`, `path_segments[]`, `depth`, `parent_sclass_id`, `order`, `name`, `cls_type`, `settings` | המצב |
| `valid_from`, `valid_to` | התקופה **המוכחת**: מהתצפית הראשונה ועד האחרונה באותו מצב |
| `change_window_start`, `change_window_end` | החלון שבו השינוי קרה: בין התצפית האחרונה במצב הקודם לראשונה בחדש |
| `change_kind` | `created` / `moved` / `renamed` / `retyped` / `settings` / `removed` |
| `moved_with_ancestor` | `true` אם הנתיב השתנה רק בגלל הזזה של אב (כמו 836690 תחת 836681) |

**`extension_type`** · מ-`/api/sclass-types/`: `cls_type`, שם, קבוצה, סכמה (JSON).

**`path_name_evidence`** · מה ההאזנות עצמן מלמדות על נתיבים. אגרגציה יומית מתוך שכבת ההאזנות הגולמית.
| שדה | תיאור |
|---|---|
| `day`, `class_path`, `class_name` | |
| `listen_count`, `first_at`, `last_at` | |
| `origin_kind` | `sfu_class_path` / `msg_record_origin` (נתיב שחולץ משם קובץ MSG) |

**החשיבות:** אם השם בנתיב מסוים משתנה בין ימים, זה סימן שהשלוחה זזה או שנתיב נוצל מחדש, גם בתקופה שאין עליה צילום.

### 4.3 שכבת הנגזר

**`path_assignment`** · הטבלה שבעזרתה משייכים כל האזנה לשלוחה: מי ישב בנתיב X בזמן T.
| שדה | תיאור |
|---|---|
| `class_path`, `sclass_id` | |
| `valid_from`, `valid_to` | |
| `basis` | `scan` (בין שתי סריקות שבהן נראה אותו מצב) / `name_continuity` (הורחב לאחור כל עוד השם בהאזנות זהה) / `assumed_current` (הונח לפי סריקה מאוחרת, בלי ראיה) / `manual` |
| `confidence` | גבוה / בינוני / נמוך, לפי ה-`basis` |
| `computed_at`, `rule_version` | לשיוך מחדש |

כל האזנה שומרת את `class_path` ו-`class_name` הגולמיים, ואת ה-`sclass_id` שנגזר, יחד עם `basis` ו-`confidence`.
כשמתווספת ראיה חדשה (סריקה, תיקון ידני), מחשבים מחדש את `path_assignment` רק לטווחים שהושפעו.

**`tree_change_event`** · אירועי שינוי לתצוגה ולהתראות: "שלוחה 836681 הוזזה, 4 צאצאים זזו איתה, בחלון 21.10 06:00–10:07".

**`extension_current`** · תצוגה של המצב העדכני של כל שלוחה, לעורך ולדשבורדים.

## 5. איך נבנית ההיסטוריה (תיאור, לא קוד)

1. כל סריקה נשמרת גולמית, ומפורקת לתצפיות.
2. לכל שלוחה, התצפיות ממוינות לפי `observed_at`. כל עוד המצב זהה, הגרסה מתארכת. שינוי פותח גרסה חדשה ומתעד את חלון השינוי.
3. אם `list` ו-`detail` סותרים באותה סריקה, נשמרות שתי התצפיות (כמו בארכיון). הגרסה נקבעת לפי התצפית המאוחרת, והסתירה נרשמת כאירוע.
4. `path_assignment` נבנה מהגרסאות:
   - בין סריקות: ביטחון גבוה.
   - בחלון שינוי: ההאזנה מסומנת "עמומה" ומשויכת לפי השם שבהאזנה עצמה (`class_name`), אם הוא מבדיל בין האפשרויות.
   - לפני הסריקה הראשונה (D-101): משייכים לפי הצילום המוקדם ביותר (`assumed_current`, ביטחון נמוך).
     כל עוד השם בהאזנות זהה לשם בצילום, הביטחון עולה (`name_continuity`).
     בנקודה שבה השם בנתיב משתנה, ההנחה נשברת: הטווח שלפניה עובר לתור "דורש החלטה", ואפשר לשייך אותו מחדש בכל עת.
   - הצילום המוקדם ביותר הוא הסריקה מ-21.10, שמיובאת כ-`tree_scan` מסוג `archive_import` (D-103).
5. הזזת אב מזיזה את כל הצאצאים. המערכת מזהה זאת לפי שינוי זהה בקידומת הנתיב, ומציגה אירוע אחד במקום מאות.

| שדה | מה עושים |

## 7. מאפייני שלוחה שהמערכת מנהלת (D-015, D-104)

המאפיינים צמודים ל-`sclass_id`. כשענף נבנה מחדש ומקבל מזהה חדש, הם עוברים דרך שורת המיפוי ישן→חדש (נושא 6), והמערכת רושמת מאיפה הגיעו.

**`extension_profile`** · שורה לכל שלוחה
| שדה | תיאור |
|---|---|
| `sclass_id` | |
| `content_type` | סוג תוכן (רשימה מנוהלת: שיעורים, הודעות, חזרה, צינתוק, הסבר, ועוד) |
| `short_description` | תיאור פנימי |
| `caller_explanation` | ההסבר שהמתקשר שומע (טקסט, ובעתיד הפניה להקלטה) |
| `renewal_rule` | תדירות חידוש: יומי / שבועי ביום X / חודשי / לא קבוע / סדרה סגורה |
| `renewal_grace` | כמה זמן אחרי המועד הצפוי להתריע על פרק שלא עלה |
| `updated_by`, `updated_at` | |

**`extension_lecturer`** · מרצים בשלוחה (מקושר לישות המרצה, נושא 4)
`sclass_id`, `lecturer_id`, `role` (ראשי / שותף / אורח), `valid_from`, `valid_to`.

**`tag`** ו-**`extension_tag`** · תגיות ונושאים
`tag(tag_id, name, kind: tag/topic, parent_tag_id)` ו-`extension_tag(sclass_id, tag_id)`.

**`extension_link`** · שלוחות מקושרות
`from_sclass_id`, `to_sclass_id`, `link_kind`, `note`.
סוגי הקישור: `mirror` (כניסה חלופית לאותו תוכן, כמו `2.6.x` מול `1.1.x`), `copy_target` ("יועתקו גם ל-310"), `redirect` ("להרשמה מועבר ל-90"), `related`.

**`attribute_change`** · יומן שינויים לכל המאפיינים
| שדה | תיאור |
|---|---|
| `entity`, `entity_id`, `field`, `old_value`, `new_value` | |
| `changed_by`, `changed_at` | |
| `source_kind` | `manual` / `inherited_via_mapping` / `suggested_from_draft` / `suggested_from_data` |
| `source_ref` | שורת המיפוי, צומת הטיוטה או הכלל שהציע את השינוי |

**העברה בבנייה מחדש:**
- הזזה (אותו `id`): לא צריך להעביר כלום.
- בנייה מחדש (1→1): המערכת מעתיקה את המאפיינים לשלוחה החדשה ורושמת `inherited_via_mapping`.
- מיזוג (N→1) ופיצול (1→N): המערכת מציעה, ומנהל מאשר אילו מאפיינים עוברים. במרצים ובתגיות ברירת המחדל היא איחוד. בשדות טקסט צריך לבחור.

## 8. נקודות פתוחות בנושא הזה

- **תדירות הסריקה.** הצעה: סריקה מלאה פעם ביום, לפני משיכת ההאזנות. ⚠️ לא ידועה מגבלת קצב ל-`system/sclass`.
  ייסגר בנושא הסנכרון.
- **שלוחות שנמחקו.** ⚠️ לבדוק אם ה-API מחזיר שלוחות שנמחקו מחיקה רכה.
- **ייבוא הסריקה מ-21.10.** צריך לקבל דוגמה של הדפים הגולמיים בנושא הייבוא (D-103).

## 9. הנחות לאימות מול ה-API

1. `order` שווה למקטע האחרון של `path`.
2. קריאה עם `parent=<id>` מחזירה רק ילדים ישירים.
3. `count_sub_sclass` סופר ילדים ישירים בלבד.
4. אין מגבלת קצב קשיחה על `system/sclass`. אם יש, הסריקה היומית צריכה להתחלק בין שעות.
5. `id` של שלוחה לא ממוחזר לעולם.
6. המשמעות של `conf_id` ו-`var_bool`.
