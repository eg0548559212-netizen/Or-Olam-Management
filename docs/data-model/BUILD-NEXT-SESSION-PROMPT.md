# פרומפט לסשן הבנייה הרביעי

מדביקים את הטקסט שלמטה כהודעה הראשונה בסשן החדש.

---

אנחנו בפרויקט Or-Olam-Management. זה **סשן הבנייה הרביעי**. הוא ממשיך את הראשון (D-109 עד D-123), את השני (D-124 עד D-129) ואת השלישי (D-150 עד D-157).

**שלב 0: חיבור**
- מחברים את המאגר `eg0548559212-netizen/Or-Olam-Management`. יש הרשאת דחיפה.
- מריצים `git pull --rebase origin main`. אם `git` נתקע ברשת, מריצים אותו עם `timeout 90`.

**שלב 1: קריאה, במלואם**
- `CLAUDE.md`
- `docs/decisions.md`
- `docs/open-questions.md`
- `docs/data-model/BUILD-HANDOFF.md`. **זו נקודת הפתיחה.**
- `docs/data-model/06-planning.md`
- `docs/design/plan-screen-ux-review.md`
- `app/README.md`
- רקע בלבד: `docs/system-spec.md`, עותק של מסמך האפיון המשותף. אם הוא סותר החלטה ב-`decisions.md`, ההחלטה גוברת, והסתירה מוצפת אליי.

**בתשובה הראשונה**
- מסכמים בקצרה מה הבנת.
- מבקשים ממני להעלות את **חבילת הסשן** (`or-olam-session-<תאריך>.zip`).
- לא שואלים על החלטות שכבר נסגרו.

**שלב 2: שחזור וסנכרון**
1. מריצים `python3 -m app.session_package restore <zip>`, ובודקים שהתשובה כוללת `key_ok: true`. אם היא אומרת שהסכמה השתנתה, בונים מחדש מקובצי המקור שבחבילה, לפי `app/README.md`. (החבילה של 30.10 כבר כוללת את `draft_node.flags`.)
2. מורידים מהדף את האוספים `decisions`, `nodeprops`, `retired` (D-152) ו-`globalnotes` (D-157), בעזרת `ArtifactData list` עם `out_dir` אל `data/page-state`. מחילים אותם על בסיס הנתונים:
   `python3 -m app.planning.apply_decisions data/page-state/decisions --props data/page-state/nodeprops --retired data/page-state/retired --globalnotes data/page-state/globalnotes`
   (אוסף ריק: יוצרים תיקייה ריקה.)
3. מריצים `python3 -m app.planning.analyze`, ואז `python3 -m app.demo.build`.
4. מפרסמים את הדף לאותה כתובת: https://claude.ai/artifact/RURYuWdBN67QoeUytV2oHD
   - קודם `read`, ורק אחריו פרסום.
   - מצהירים על אותן יכולות: `{"db": {}, "user": {"scopes": ["profile"]}, "downloads": true}`.

**בסוף הסשן (D-123)**
1. מושכים שוב את מצב הדף ומחילים אותו.
2. מריצים `analyze`.
3. מריצים `python3 -m app.session_package save`.
4. שולחים לי את הקובץ.

**ההמשך**
אשאל אותך מה הלאה. ההמלצה ב-`BUILD-HANDOFF.md`:
1. להמשיך לפי הבקשות שלי בתכנון העץ.
2. המסכים שעוד לא אופיינו (סטטיסטיקה, מאזינים ועוד) צריכים נתוני האזנה, ו-D-109 לא כולל אותם. לפני שמתחילים בהם, מבקשים ממני אישור מפורש.

**כללי עבודה**
- **שאלה אחת בכל פעם,** עם המלצה. לא שואלים מה שאפשר להכריע לבד מתוך הקוד, המסמכים או ברירת מחדל סבירה. במקרה כזה מחליטים, ואומרים מה הוחלט.
- **השפה היא עברית,** גם בשיחה וגם במסמכים.
- **מקור האמת הוא `docs/decisions.md`.** רק מוסיפים אליו. החלטה שמשתנה מקבלת מספר חדש, והישנה מסומנת "הוחלפה ב-…" או "עודכנה ב-…".
- **לא משנים החלטות D-0xx.** סתירה להחלטה קיימת או לאפיון v0.7 נרשמת ב-`open-questions.md`, עם מי שמכריע בה, ומוצפת אליי. לא מכריעים בה לבד.
- **מספור:** החלטות חדשות D-158–D-169. שאלות חדשות Q-142–Q-159. (D-130–D-149 ו-Q-120–Q-139 שייכים לסשן השיעורים.)
- **בסוף כל שלב** מעדכנים את המסמכים, עושים commit ודוחפים ל-main.
  - לפני דחיפה מריצים `git pull --rebase origin main`, כי סשנים אחרים כותבים למאגר.
  - לא עורכים קובץ שסשן אחר עובד עליו.
- **שינוי בממשק:** קודם מכינים הדמיה ומקבלים אישור, ורק אחר כך כותבים קוד. אחרי המימוש בודקים בדפדפן אוטומטי לפני הפרסום.
- **עיצוב:**
  - אותם צבעים, אותו תפריט ימני ואותו סרגל עליון כמו בדף הקיים.
  - בסרגל העליון כתוב "מנהל הקו".
  - אין התאמה לנייד (D-125).
  - טפסים: תווית גלויה לכל שדה, שמירה בלחיצה (D-127), ונגישות מלאה.
- **פרטיות ואבטחה:**
  - לא מכניסים למאגר נתונים גולמיים, נתוני האזנה, מספרי טלפון, מפתחות או טוקנים. כל אלה נשמרים רק תחת `data/` ו-`.env`, שמוחרגים מהמאגר.
  - טוקן ה-API של ידע פון נשמר רק כמשתנה סביבה.
  - לא כותבים לידע פון. מותרות רק קריאות `GET` (D-007).
  - חבילת הסשן כוללת את המפתח, ולכן היא נשמרת רק אצלי.
